# alpha1 本地基准工具

仅使用 Node 标准库；不会把请求转发到外部服务。基准文字是固定测试数据，图像编辑接口回传上传图，不能评价真实翻译质量。

双击 `启动测试服务器.bat`，或在本目录运行：

```powershell
node server.cjs --delay 3000
```

图片目录默认 `E:/codexwork/漫画`，只服务其中自然排序的前 30 张 PNG/JPG/WebP。可用 `--images "目录"` 更换。普通网页 `/`，懒加载网页 `/?lazy=1`，状态 `/health`，API 前缀 `/v1`。端口默认 8787；以服务器打印的可访问局域网地址为准。

手机 Key 使用 `local-test-key-111`，不要填写真实 Key。文字模型 `mock-text`；图像模型 `mock-image`。金标准使用文字模式，`normal` 场景。

参数：

| 参数 | 值 |
|---|---|
| `--delay` | `0` 或 `3000`，毫秒 |
| `--scenario` | `normal`、`long`、`vertical`、`skip`、`missing`、`truncated`、`mixed` |
| `--rate429` / `--rate503` | 0–100 整数，合计不超过100；按请求序号在100次窗口中确定性注入 |
| `--port` | 端口，默认8787 |
| `--host` | 默认 `0.0.0.0`，本机检查可指定 `127.0.0.1` |

注入错误和缺失/截断的场景用来观察失败与重试，不作为“完整成功的30页金标准”。日志只打印请求摘要、内容指纹及相同请求出现次数，不打印请求图片、文本或鉴权头。不同裁切批次的指纹会不同，不能据此证明跨批次没有重复调用。

支持 `/v1/models`、`/v1/chat/completions`、`/v1/responses`、`/v1/images/edits`。局域网地址下应用沿用现有 Chat Completions 路径；Responses 的服务器协议由主机检查覆盖，没有修改应用的协议选择逻辑。

主机检查：

```powershell
node check.cjs
node analyze-check.cjs
```

分析用户导出的完整日志：

```powershell
node analyze.cjs "浏览器3秒冷.jsonl" "分析输出"
node analyze.cjs "后续版本.jsonl" "对比输出" "alpha1基线.jsonl"
```

默认只分析最新导出状态对应的采集段，要求至少30页。输出 `分析.json`、`内存曲线.csv` 和 `基线报告.md`。日志轮转、缺少身份、读回不匹配、失败页、缺少主图或记录不足时返回非零退出码，不能给出通过结论。

同一场景、同一手机、同一组图片、同一设置进行对比。不同延迟或冷/热状态分别开一段诊断并导出，不合并平均。每次关闭后再开启“诊断记录”开始新段；冷/热之间保留应用进程。没有手机日志时不生成伪基线。

完整手机步骤见项目 `交付/1.1.1-alpha1构建与诊断说明.txt`。
